# 题库录入格式

把实体书扫描资料整理成题目，写在本目录的 `.md` 文件里，然后运行：

```bash
node tools/qbank/build.mjs          # 编译进 App 的 BookContent.kt
node tools/qbank/build.mjs --check  # 只校验，不写文件
```

编译结果会进入 `app/src/main/java/com/ascent/climb/data/BookContent.kt`，
再由 `bash tools/contentcheck/run.sh` 导出成在线题库 `bank/bank.json`。

## 约定

| 文件 | 用途 |
|---|---|
| `README.md` | 本说明，不参与编译 |
| `_开头.md` | 草稿 / 试写 / 测试，**不参与编译** |
| 其它 `*.md` | 会被编译进题库 |

录入原则：**只取书中的知识与技术事实，用自己的话重写题干与解析**，并填写 `来源：`
标注到具体页码。避免逐字摘抄原文（版权与可读性双重原因）。

## 一、新增一门课程

````markdown
# 课程 l23 · 冰锥放置进阶

- unit: u5
- code: ICE SCREW
- icon: 🧊
- needsCoach: true
- book: 《登山圣经》第 5 版

## 要点

- 冰锥应打入冰质密实处，避开空腔与蜂窝冰。
- 打锥角度略向下倾，受力方向顺着预期坠落方向。

## 题目

1. 打冰锥之前，最应该确认的是？
   - 冰锥的颜色是否醒目
   - 该处冰体是否密实，有无空腔或蜂窝化
   - 附近是否有其他队伍
   - 冰锥离地面的高度
   答案：B
   来源：《登山圣经》第 5 版 p.214
   解析：冰锥的强度不取决于放置技巧，而取决于冰本身。打在空腔或蜂窝冰上的冰锥几乎无法承受坠落冲击。

2. 第二道题……
````

### 元信息字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `unit` | ✅ | 挂到哪个营地：`u1`~`u5` |
| `id` | | 课程 id，留空自动生成 `b1`、`b2`… |
| `code` | | 英文代号，显示在课程标题下 |
| `icon` | | 一个 emoji |
| `needsCoach` | | 是否属于需要教练现场评估的实操技能 |
| `book` | | 主要参考书，仅作备注 |

> 新增课程会**追加在该营地的末尾**，因此路线顺序 = 营地内已有课程 → 新课程。

## 二、给已有课程追加题目

````markdown
# 追加 l13

## 题目

1. 题干……
   - 选项 A
   - 选项 B
   答案：A
   来源：《高原医学》p.88
   解析：……
````

适合「这本书里有一道好题，正好补进 AMS 那一课」这种场景。

---

## 三、题目字段

| 写法 | 含义 |
|---|---|
| `1. 题干` | 题号 + 题干（必需） |
| `   - 选项` | 选项，两个以上（必需，缩进两个空格） |
| `答案：B` | 正确答案，支持 `A`–`E` 或数字（必需） |
| `解析：…` | 解析，显示在答完之后（强烈建议填） |
| `来源：…` | 知识来源，显示在解析下方（建议填到页码） |
| `情境：…` | 可选的情境说明，显示在题干下方 |
| `安全：是` | 标记为安全关键题（加权、答错必须理解后才能继续） |

**续行**：`解析` / `来源` / `情境` 后面缩进的普通行会自动接到上一个字段，
方便写多段解析。

**容错**：全角 `：` 与半角 `:` 都可以；`答案：b` 小写也可以。

---

## 四、编译时的检查

编译会用红线拦住这些问题（有错就不写文件）：

- 题干为空
- 选项少于 2 个
- 答案超出选项范围 / 无法识别
- 课程缺少 `unit`、`id` 或标题
- 某个块一道题都没有

以下只提示不阻断：

- 缺少 `解析`
- 技能要点为空
- 未知的元信息字段或二级标题

## 五、完整流程

```bash
# 1. 把扫描件整理成 import/xxx.md
# 2. 编译并校验
node tools/qbank/build.mjs

# 3. 重建 App（内置题库会带上新内容）
cd ~/AscentApp && "$HOME/android-toolchain/gradle-8.9/bin/gradle" assembleDebug

# 4. 校验 + 导出在线题库（会顺带检查题量、难度递增、解锁逻辑）
bash tools/contentcheck/run.sh

# 5. 把 bank/bank.json 与 bank/manifest.json 传到服务器 —— 用户不发版即可更新

# 6. 如果改了内置内容，记得把 data/bank/BankConfig.kt 的 BUNDLED_VERSION +1
```
